# Flux Music Player v1.0.20+21 - 更新说明

## 🎉 主要新功能

### 扫描结果本地持久化

**解决的问题**：
- ❌ 之前：每次重启应用后，扫描结果丢失，需要重新扫描
- ✅ 现在：扫描结果自动保存，应用启动时立即恢复

**用户体验改进**：

| 场景 | 之前 | 之后 |
|------|------|------|
| 冷启动 | 空白，需要点击扫描 | 立即显示之前的库 |
| 重启应用 | 需要重新扫描（数分钟） | 秒级加载完成 |
| 网络不稳定 | 扫描中断后全部丢失 | 可从缓存快速恢复 |

## 🔧 技术实现

### 新增组件

1. **缓存存储库** (`LibraryScanCacheRepository`)
   - 自动管理扫描结果的保存和加载
   - 支持多个音源的独立缓存
   - 智能错误恢复

2. **JSON 序列化**
   - `LibrarySong` 模型支持 JSON 格式
   - 可靠的数据持久化
   - 易于调试和检查

3. **自动保存**
   - 扫描完成后自动保存到缓存
   - 应用启动时自动加载缓存
   - 无需用户手动配置

### 新增依赖

```yaml
shared_preferences: ^2.2.3   # 预备存储偏好设置
path_provider: ^2.1.3        # 应用缓存目录访问
```

## 🔄 升级说明

### 从 v1.0.19 升级

升级后应用会：
1. 自动检测是否有本地缓存
2. 如果有，立即加载并显示库
3. 如果没有，首次启动时执行一次扫描建立缓存

**无需手动操作，完全自动！**

## 📝 使用指南

### 日常使用

1. **首次启动**
   ```
   打开应用 → 显示空库 → 点击"扫描" → 添加音源并扫描 → 结果保存
   ```

2. **后续启动**
   ```
   打开应用 → 立即显示库 → 可以直接播放
   ```

3. **更新库**
   ```
   添加新歌曲到远程存储 → 点击"扫描" → 新歌曲显示 → 自动保存
   ```

### 高级操作

#### 清空缓存（重新开始）

在应用内手动触发（需要在代码中调用）：
```dart
final cacheRepo = await createScanCacheRepository();
await cacheRepo.clearAll();
```

或通过以下方式：
1. 卸载并重新安装应用
2. 清空应用数据

#### 重新扫描单个源

只点击某个音源的"重新扫描"按钮，会：
- 仅更新该源的缓存
- 保留其他源的数据
- 快速完成（增量更新）

## 🐛 故障排除

### 问题：缓存文件损坏

**症状**：应用启动闪退或显示 JSON 错误

**解决方案**：
1. 清空应用缓存：设置 → 应用 → Flux Music → 存储 → 清空缓存
2. 重启应用
3. 点击"扫描"重建缓存

### 问题：库显示不完整

**症状**：某些歌曲缺失

**解决方案**：
1. 点击"扫描"刷新库
2. 如果仍有问题，清空缓存后重新扫描

### 问题：占用空间过大

**症状**：缓存文件超过预期大小

**解决方案**：
1. 清空缓存：见上文
2. 计划未来版本实现压缩功能

## 🔒 隐私和安全

### 缓存内容

缓存文件包含以下信息：
- 歌曲标题、艺术家、专辑
- 文件路径和远程 URL
- 扫描元数据（日期、时间等）

### 隐私保护

- ✅ 缓存存储在应用私有目录（仅应用可访问）
- ✅ 不包含敏感凭证（用户名/密码存储在 flutter_secure_storage）
- ✅ 不与服务器同步
- ✅ 用户可随时清空

## 📋 已知限制

1. **没有增量更新**
   - 每次扫描都会完整更新该源的缓存
   - 对于大型库可能略慢，但仍快于首次扫描

2. **没有缓存压缩**
   - 缓存是明文 JSON 格式
   - 对于超大型库（10000+ 首歌），可能占用较多空间

3. **没有自动过期**
   - 缓存持续有效，直到手动清空
   - 可能导致显示已删除的歌曲

4. **没有云同步**
   - 缓存仅限本地设备
   - 多设备使用时需要各自扫描
